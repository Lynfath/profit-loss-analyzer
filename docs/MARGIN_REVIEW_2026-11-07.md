## 정의와 반올림 정책

원가를 C, 판매가를 P, 비율을 r이라 할 때 VAT 별도 기준이다.

| 기준 | 정의 | 판매가 계산 |
| --- | --- | --- |
| 원가 가산율 | (P−C) / C | P = C × (1+r) |
| 매출총이익률 | (P−C) / P | P = C / (1−r), r < 100% |
| 최종 영업이익률 | (매출−직접원가−선택 인프라원가−일반관리비) / 매출 | 현재 예상손익 집계 기준 |

원가 가산율 r을 적용했을 때 실제 매출총이익률은 r/(1+r)이다. 일반관리비는 매출총이익 계산 이후에 차감한다. 현재 앱에서 선택적으로 매입원가에 합산하는 센터 인프라는 집계 매출총이익에도 영향을 준다.

기존 방식은 10원 단위 반올림(기존 tie-to-even 동작 포함)을 유지한다. 신규 매출총이익률 방식은 Decimal로 역산하고 10원 단위 올림하여 양수 원가의 목표율을 반올림 때문에 밑돌지 않도록 했다. 이 정책으로 실제 단가 이익률이 목표보다 높을 수 있으며, 낮은 단가에서는 차이가 커질 수 있다. 원가 0원인 창고 항목은 기존 수동 판매단가를 유지한다. 특송 원가 0원 항목은 기존 자동계산 동작에 맞춰 0원이 된다.

가상 창고 월 100건, 매입단가 10,000원(직접 영업원가 1,000,000원), 인프라 원가 월 100,000원, SG&A는 창고 운영매출의 7%, 특송은 합산하지 않는다. 실제 손실 발생을 주장하는 예시가 아니다.

따라서 신규 단가 모드의 20%는 개별 매입단가 기준 목표이다. 이 예에서 인프라 포함 매출총이익률은 12%, SG&A 차감 후 영업이익률은 5%가 된다. 전체 원가를 포함한 최종 매출총이익률 20%를 보장하려면 단가별 인프라 배부 등 추가 가격정책이 필요하다. 창고만 있는 위 예에서는 전체 월 매출을 (직접원가+인프라)/(1−목표율)로 역산할 수 있지만, 이를 기존 단가별 가격정책에 자동 적용하는 변경은 하지 않았다.

## 수정 방식과 호환성

탭 4·5·6에 공통 산정 기준 선택을 추가했다. 기본값은 **원가 가산율 (기존 방식)**이다. 기존 세션의 숫자 입력값, 수동 단가, 물동량, 비고와 기본 예시는 재계산하지 않는다. **목표 매출총이익률**을 선택한 다음 재계산 버튼을 누르거나 탭 6의 특송 비율을 변경할 때만 역산식이 적용된다. 기준 선택 자체는 단가를 바꾸지 않는다.

기존 데이터프레임 컬럼, 입력 위젯 키, 세 다운로드 파일명, 시트명·열·행·견적서 양식, `build_quote_workbook` 시그니처를 유지했다. 엑셀은 선택한 기준으로 계산된 저장 단가를 그대로 출력하고, 다운로드 과정에서 단가를 재계산하지 않는다. 결과 셀과 퍼센트 문자열의 기존 출력 형식도 유지한다. 단가 모드 설명은 앱에 표시하며 견적서 서식에 새 행·열을 추가하지 않는다.

탭 6의 숫자·특송 포함 입력은 콜백으로 공통 상태에 먼저 반영하여 동일 실행의 앞쪽 탭 다운로드도 갱신한다. 특송의 매출 0원 경로는 UI와 엑셀 모두 분모 검사를 추가했다. 0매출의 이익률 `0.0%`는 표시 관례이며 수학적으로 정의된 비율은 아니다.

기존 동작을 전부 매출총이익률 방식으로 교체하는 대안도 검토했다. 그러나 기존 20 입력은 기존 방식에서 12,000원, 새 방식에서 12,500원이 되어 저장된 단가와 사용자의 기대가 바뀐다. 명시적인 의도 확정 근거가 부족한 상태에서 호환성을 유지하기 위해 기존 방식의 명칭을 바로잡고 신규 방식을 선택하도록 했다.

## 회귀 검증과 재현

최종 결과: **115개 테스트 PASS, FAIL 0, SKIP 0**. 실행 시간 82.65초. 이 중 가격·비용 조합은 4개 비율 × 2개 산정 방식 × 특송 포함/제외 × 인프라 포함/제외 = **32개 시나리오**이며 각 시나리오에서 UI 집계와 다운로드 3개를 검증했다.

가상 특송 데이터는 매입단가 10,000원·20,000원, 발송비중 75%·25%, 월 200건이다. 가중평균 단가는 비중 합계로 나누어 계산하고 창고·특송 매출과 원가를 각각 검증했다. SG&A는 특송 매출에 배부하지 않는 기존 정책을 유지했다. 별도 테스트로 SG&A 0%·15%, 특송 0건, 판매가 0원, 창고 원가 0원, 수동 단가·비고·단위·매입원가·발송비중 편집, 모든 특송 조정 경로, 기존 세션 초기화와 가상 원장 업로드를 검증했다.

기대값은 Fraction 유리수 연산으로 별도 계산했다. 신규 생산 계산 함수의 반환값을 다시 기대값으로 사용하지 않는다. UI는 실제 Streamlit AppTest로 조작하고, `Workbook.save`에서 생성된 실제 XLSX 바이트를 읽어 세 다운로드의 값과 셀 서식을 대조했다. 원본 main도 별도 실행하여 10·15·20·30% 결과, 세 특송 진입점, 다운로드 최신성, 0건 이익률을 재현했다.
